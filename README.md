# Damage Bug Finder for NTE / 异环 NTE 数值验算器

还在为找不到伤害异常，发现不了命座失效，拿不到环石奖励而发愁吗？

还在为嘉豪被动错误，真红上线修bug，伊洛伊6命座错3个等奇异搞笑现象而愤懑不满吗？

Damage Bug Finder，一款面向《异环（NTE）》测试服玩家的数值检查工具，让你轻松拷打苏幻程序员，期期环石1000+！

它可以按伤害公式正向计算伤害与治疗，也可以把打出的伤害跳字交给多组“生效/失效”假设反向验算，找出最能同时解释整批数据的 Buff 状态、技能倍率和伤害来源，快速判断是否有乘区失效。

离线版本包含基础计算、反向验算、角色档案和 OCR 等功能；Windows 桌面版另提供可选的实验性抓包功能。

![Damage Bug Finder for NTE 界面总览](docs/images/01-overview.png)

## 核心能力

| 场景 | 可以完成的工作 |
| --- | --- |
| 正向计算 | 计算常规伤害、持续伤害、创生、浊燃、黯星三大环合反应伤害和治疗值，同时保留内部小数。 |
| 常规验算 | 已知技能来源时，固定基础区，只判断觉醒、武器、弧盘、共鸣或队友 Buff 是否实际生效。 |
| 狂暴溯源 | 面对一批不知道来源的跳字，反推技能、暴击状态、倍率来源、共同 Buff 的生效状态，甚至是基础面板失效。 |
| 倍率排错 | 记录多个技能倍率，检查技能是否误用了其他技能的倍率。 |
| 档案保存 | 按“角色名称 + 游戏版本”保存完整配置，并自动记忆当前草稿。 |
| 面板 OCR | 桌面版自动截取游戏窗口，使用 Windows 本机 OCR 读取基础面板，不上传截图。 |
| 抓包辅助（实验性） | 接入用户自行提供的 `nte-core.exe`，自动接收伤害增量、GA/GE 身份并映射到现有技能或环合反应。 |

## 下载与运行

### Windows 桌面版（推荐）

从仓库的 [Releases](../../releases/latest) 下载：

```text
DamageBugFinderForNTE-v0.9.7-Windows-x64.zip
```

完整解压后运行：

```text
DamageBugFinderForNTE\DamageBugFinderForNTE.exe
```

不要直接在 ZIP 中运行，也不要只复制 EXE。程序需要同目录的 `_internal` 文件夹。

桌面版不要求安装 Python，基础计算不联网；OCR 需要 Windows 10/11 的简体中文 OCR 语言组件。抓包辅助为可选功能，发行包不会捆绑、下载或修改第三方解析核心。若 Windows 弹出未知发布者提示，可在确认文件来自本仓库后选择“更多信息 → 仍要运行”。

### 单文件 HTML 版

直接下载并双击仓库根目录的 `index.html`。它支持计算、验算、狂暴溯源和浏览器本地档案，但不支持自动捕获游戏窗口及 Windows OCR。

`index.html` 也是静态站点入口，可直接部署到 GitHub Pages 或其他静态托管服务。抓包辅助仅在 Windows 桌面版中工作。

## 四步工作流

界面中的编号对应真实操作顺序：

1. `01 BASELINE`：填写角色、目标和基础乘区。
2. `02 VARIABLES`：加入可能生效或失效的 Buff。
3. `03 OBSERVED`：录入技能倍率及游戏实测值。
4. `04 TRACE`：选择验算模式和搜索强度，开始排查。

![角色档案与基础面板](docs/images/02-profile-panel.png)

顶部的“伤害计算 / 治疗计算”会切换整套输入界面。角色档案按角色和版本归档；“保存/覆盖”保存当前全部字段，“清空当前”只清空草稿，不会删除已保存档案。

## 使用场景

### 常规验算：已知是哪一个技能

适合确认某次攻击是否正确吃到了指定觉醒、武器或其他 Buff。

1. 填写角色与敌人面板。
2. 在 Buff 区加入所有可能生效的效果；高把握效果可勾选“高触发优先”，确定生效的效果可设为“锁定生效”。
3. 添加一个或多个伤害技能，填写倍率、伤害 Tag、暴击状态和实测显示伤害。
4. 选择“常规验算”，通常保持“深度”搜索。
5. 点击“确定并开始验算”。

![常规验算及零误差结果](docs/images/03-verification-results.png)

程序会把同一个候选状态应用于本批全部实测值，最上方是排序第一的全局解释。只有整批显示值总误差为 `0` 的备选状态，才会进入“零误差全局状态”列表。

### 狂暴溯源：只看到一批未知跳字

适合实战中同时出现多段伤害、无法确认每个数字来源的情况。

1. 先录入角色、目标、Buff 和所有可能的技能倍率。
2. 勾选需要加入来源池的技能。
3. 切换到“狂暴溯源”。
4. 将未知伤害用空格、逗号、分号或换行批量粘贴。
5. 点击“确定并开始溯源”。

![狂暴溯源输入与结果](docs/images/04-rage-tracing.png)

每条未知伤害都会尝试候选技能、创生花、浊燃、黯星、暴击 / 非暴击和其他已记录倍率。同一来源允许重复，但整批跳字必须共享同一套面板与全局 Buff 状态。

常规验算不会尝试基础区失效；狂暴溯源才会把与候选伤害来源有关的基础区加入失效搜索，并在同等误差下优先保留基础区正常的解释。

程序只汇报显示值误差在 `±20` 内的来源。相差几十或几百的结果不会被强行解释。

### 治疗验算

切换到“治疗计算”后，敌人、防御、抗性、增伤、浸染 / 覆纹乘区会隐藏，只显示治疗需要的攻击、治疗加成、候选 Buff 和治疗技能。

![治疗计算模式](docs/images/05-healing-mode.png)

治疗 Buff 与伤害 Buff 使用相同的生效 / 失效验算逻辑。

### 自动读取游戏面板（仅桌面版）

点击“角色与目标面板”中的“自动读取游戏面板”即可打开 OCR 工具。

![本机 OCR 截图识别窗口](docs/images/06-ocr-dialog.png)

推荐捕获三次：

1. 角色信息总览；
2. 属性详情上半段；
3. 滚动后的增伤与属性区域。

选择游戏窗口和倒计时后点击“捕获当前面板”。计算器会暂时隐藏并切回游戏；可趁倒计时打开详情或滚动面板。多张截图会按字段名称合并去重，确认识别值后再写入计算器。

当前可自动填写：

- 非战斗面板攻击与基础攻击；
- 角色等级；
- 面板暴击伤害；
- 通用增伤；
- 光、灵、咒、暗、魂、相、心灵七种属性中的有效属性增伤；
- 环合强度；
- 治疗加成。

暴击伤害按游戏面板原值导入。例如 OCR 读到 `134%` 时填入 `134`，计算时自动转换为 `1 + 134% = 2.34` 倍。

生命、防御、体力、暴击率、充能效率、倾陷强度及受治疗加成不会写入计算器；敌人等级、敌人抗性、防御穿透和抗性削弱仍需手动填写。截图与识别均在本机完成，程序不会保存完整截图，也不会导入画面中的 UID。

### 抓包与事件学习（实验性）

顶部点击“抓包 / EVENT LEARN”打开事件时间线。该功能通过本机标准输入输出与用户自行提供的 [`nte-core.exe`](https://github.com/kongbaiz/nte-dps-toolkit) 通信；本仓库及 MIT 发行包不包含该第三方程序。

![抓包与事件学习](docs/images/09-capture-event-learning.png)

首次使用：

1. 按第三方项目说明准备 Npcap 和可用的 `nte-core.exe`；测试服版本若协议或封包结构不同，需要相应版本的解析核心。
2. 在“解析核心路径”选择该 EXE，点击“开始抓包”。路径只保存在本机。
3. 在游戏内进行动作后查看“原始事件预览”。测试服载荷中可读的 `Melee`、`Skill`、`Reaction`、`CritDamage`、`GA` / `GE` 等名称会按毫秒时间排列；点击复制按钮可保存内部名称。
4. 如果游戏显示了伤害，在“游戏显示伤害”填写该整数。程序会在事件前后 0.35 秒的候选数值中只保留误差 `±20` 的匹配并按误差排序。可再填写角色事件关键字，例如 `Sagiri` 检索 `GA_Sagiri_*`，并保留与该角色 GA 相邻的 ASC 载体记录。
   `AbilitySystemComponent` 会标为“载体”：它负责同步伤害结果，但名字本身不能区分具体技能。
5. 选择某一次匹配记录，在“选中记录映射到”指定已有技能、创生花、浊燃、黯星或新建技能，再使用底部按钮送入常规验算或狂暴溯源。导入的是游戏实测显示值；倍率和暴击状态仍需人工确认。
6. 需要使用标准 Core 已解析的伤害摘要时，可在释放技能前填写“本次游戏动作标记”并点击“现在标记”，随后 12 秒内的新伤害会带上该标记。
7. 查看事件名称、类别、`GA` / `GE` 身份、伤害增量和 Hit 数，将事件映射到现有技能、创生花、浊燃、黯星或新建常规技能。
8. 勾选可信的 `1 HIT` 摘要，送入常规验算或狂暴溯源。抓包摘要没有可靠暴击标记，写入后仍需人工确认暴击状态。

需要注意：
1. “Core 通知审计”只记录解析核心主动上报的方法、参数结构、字符串标识和少量标量样本。Core 的启动、运行、停止状态始终显示；角色/内部名只过滤内容通知，因此填写 `Zankou` 后也不会把运行状态误隐藏。若提示“只有运行状态”，表示 Core 没有导出 Buff/战斗内容通知，并不表示原始 PCAP 中没有 Zankou。战斗摘要默认隐藏，避免累计摘要淹没未知 Effect 通知。精简审计日志保存在`%LOCALAPPDATA%\GameDamageCalculator\capture\core_audit_*.ndjson`；payload、网络端点和身份字段不会写入日志。

2. “原始事件预览”来自程序直接扫描 PCAP 中可读的 Unreal 名称，与 Core 通知审计是两条独立数据来源。条目中的“位移 N bit”表示为了还原跨字节 ASCII 名称所作的位重组，不是包长；实际 UDP 载荷长度会单独显示为“包长 N B”。

3. 已确认的事件映射按“角色名称 + 版本”保存在本机。当前会将包含 `Reaction_1` 的伤害视作创生花候选，将包含 `Reaction_5` 的伤害视作浊燃候选；测试服出现新命名时，应以实际事件和手工映射为准。

4. 标准 Sidecar 的战斗摘要最高约每 250 ms 更新一次，不含逐击原始记录：一次增量恰好为 `1 HIT` 才能直接作为单段实测值；多个 Hit 被合并时只显示多段合计，工具会禁止将其写成某一段。原始事件预览是独立的测试服发现工具，不会把任意浮点数伪装成已解析伤害。若通知审计没有发现 Buff apply/remove/stack 方法，则表示当前 Core 公开接口未输出这些事件，Buff 数值及候选状态仍由计算器手工维护。

5. 为实现事件预览，本程序会显式启用原始 PCAP，并只在本机增量读取已经完整写入的数据块；不会在界面显示 payload、IP 或端口。文件保存在 `%LOCALAPPDATA%\GameDamageCalculator\capture`，停止抓包后仍会保留，长时间测试时请留意磁盘占用。原始 PCAP 可能包含当前网卡的其他流量，不应上传到公开仓库、Issue 或聊天。停止抓包或关闭计算器时，辅助进程会一并退出。第三方项目采用其自己的 AGPL / 商业许可，使用、分发或修改时请单独遵守其许可证；本项目自身采用 MIT License。

## 字段填写规则

### 角色档案

| 字段或操作 | 规则 |
| --- | --- |
| 角色名称 | 与版本共同组成档案键，建议使用游戏内角色名。 |
| 版本 | 建议填写可复现的游戏版本，例如 `1.4.0`。 |
| 保存/覆盖 | 保存面板、Buff、技能、模式和搜索强度；同名档案会覆盖。 |
| 载入 | 使用所选档案替换当前输入。 |
| 删除 | 永久删除所选本地档案。 |
| 清空当前 | 清空当前草稿，保留已保存档案。 |

未主动保存时，程序仍会自动记忆当前草稿。

### 01 · 角色与目标面板

| 字段 | 单位与填写方式 |
| --- | --- |
| 非战斗面板攻击 | 填角色未进入战斗时的最终面板攻击。不要预先加入战斗 Buff。 |
| 基础攻击 | 填属性详情中攻击力左侧的白色基础数值。 |
| 基础战斗攻击加成 | 填百分数；`20` 代表 `20%`。 |
| 基础治疗加成 | 仅治疗模式显示，填游戏面板百分数。 |
| 角色等级、敌人等级 | 填整数，进入防御区公式。 |
| 敌人基础抗性 | 填百分数。敌人属性抗性可参考[敌人数据表一](https://docs.qq.com/sheet/DUGxzWGhNc2RsZ3B0?tab=dfjfo3)和[敌人数据表二](https://docs.qq.com/sheet/DUFFaVGFDRmxaRUF6?tab=000001)。 |
| 基础环合强度 | 非战斗面板值，合法范围 `0～360`；创生花、浊燃、黯星、浸染或覆纹需要时显示。Buff 结算后的最终值不设上限。 |

基础伤害乘区也位于 `01` 面板区内：

| 字段 | 规则 |
| --- | --- |
| 防御穿透 | 填 `20` 即按 `0.20` 进入防御区。 |
| 抗性削弱 | 与抗性区加算。 |
| 通用 / 属性 / 额外增伤 | 三者与基础倍率 `1` 加算形成增伤区。 |
| 面板暴击伤害 | 直接填写游戏显示百分数，程序自动补基础倍率 `1`。 |
| 浸染 / 覆纹乘区 | 在 Buff 区选择“浸染”或“覆纹”后，常规伤害乘 `1 + 20% + 最终环合强度 / 1400`；两者不能在一次验算中重复叠加。 |

常规验算固定基础区；狂暴溯源才会检查相关基础乘区整体或单个基础数值是否未生效。

### 02 · Buff 区

候选效果包括觉醒、被动、弧盘、共鸣、队友等 Buff。每一行代表一个可独立判断生效或失效的效果。

Buff 区顶部可直接选择“未启用 / 浸染 / 覆纹”。选择后会显示一张独立卡片；该乘区自动读取当前验算假设中的最终环合强度，因此候选 Buff 提供的环合强度生效或失效时，浸染 / 覆纹倍率也会同步变化。

- `高触发优先`：表示测试时更确信该 Buff 已触发。它只在计算误差等主要条件相同的状态之间调整解释顺序；取消勾选不会排除该 Buff，也不会减少搜索范围。
- `参与搜索`：默认状态，允许程序比较该 Buff 生效、部分失效或完全失效。
- `锁定生效`：该 Buff 所有被当前公式读取的属性必须生效，是“高触发优先”的绝对版本。自动叠层 Buff 仍会反推层数，但不会尝试 0 层。
- `挂起排除`：整张 Buff 卡片暂时不进入公式、不生成搜索维度，也不会出现在验算结果中；数值仍保存在档案内，之后可以恢复。
- `作用：全部技能`：点击后可改成仅持续伤害、仅非持续伤害或自定义技能。只有“自定义”才显示逐技能勾选，避免常驻的 Buff × 技能复选框矩阵。
- `叠层 Buff`：默认关闭，普通 Buff 的操作不变。仅层数型 Buff 开启，如咒属性卡带、残虹专武，甚至是早雾被动计数的DoT数量增伤，都可以使用叠层buff计算；开启后该目录下所有非零Buff均解释为单层数值。

层数方式可以选择“自动反推”或“固定层数”。自动反推会搜索 `0～最大层数`，例如最多 6 层只增加 7 个互斥候选状态；固定层数用于已知当前层数的测试，同时仍可判断整项是否未生效。单行多个属性始终共享同一层数。

搜索前会按当前纳入验算的技能裁剪 Buff 属性。例如只验算浊燃时，攻击加成、普通技能倍率和非自定义点名的普通增伤不会进入排列；普通持续伤害仍会读取攻击、防御穿透、抗性削弱、常规增伤、技能倍率、持续伤害强化及实际勾选的暴击区。作用范围不覆盖当前技能的 Buff 同样不会占用排列数量。

![Buff 自定义作用技能](docs/images/07-buff-scope-dialog.png)

![叠层 Buff 自动反推](docs/images/08-stack-inference.png)

| 字段 | 进入的计算位置 |
| --- | --- |
| 攻击加成 | 与其他攻击加成相加，再乘基础攻击后加入战斗面板。 |
| 防御穿透 | 加入防御穿透总和。 |
| 抗性削弱 | 加入抗性削弱总和。 |
| 增伤 | 加入 `1 + 通用 + 属性 + 额外 + Buff` 增伤区。 |
| 持续伤害强化 | 独立按 `1 + 生效 Buff 总和` 计算，只作用于持续伤害 Tag 与浊燃。 |
| 暴击伤害 | 与面板暴击伤害加算，不会再次增加基础倍率 `1`。 |
| 技能倍率 | 默认与技能基础倍率加算。 |
| 技能倍率乘算 | 勾选后改为 `基础倍率 × (1 + 提升)`；多个乘算项连乘。 |
| 环合强度提升 | 百分比提升，先乘基础环合强度。 |
| 环合强度固定提升 | 在百分比提升后加固定数值 `+x`。 |
| 治疗加成 | 加入治疗加成区，仅治疗模式显示。 |

普通 Buff 同一行填写多个提升，表示这些提升共享优先级和技能作用范围，程序仍会检查行内单项是否未生效。叠层 Buff 的多个提升还会绑定到同一层数，不逐属性使用不同层数。数值为 `0` 的字段不会形成判断项。

### 03 · 技能与实测值

伤害技能字段：

| 字段 | 规则 |
| --- | --- |
| 技能名称 | 自定义名称，建议与游戏内名称一致。 |
| 伤害模型 | “常规”读取攻击和各伤害乘区；“创生花”固定基础值 `9000`；“浊燃”固定基础值 `2700`；“黯星”固定基础值 `45000` 且无视防御, 该基础值默认游戏角色为80级。 |
| 伤害 Tag | 常规技能可标为“持续伤害”，并因此读取持续伤害强化乘区；浊燃固定为持续伤害。 |
| 基础倍率 | 仅常规技能显示。填 `240` 代表 `2.40` 倍；创生花、浊燃和黯星不读取普通技能倍率，因此隐藏此字段。 |
| 实测显示伤害 | 填游戏最终显示的整数。 |
| 暴击 | 常规验算时指定该条实测值是否暴击。 |
| 作为候选来源 | 决定该技能是否进入狂暴溯源来源池。 |

可以记录多个技能。常规验算优先使用本技能倍率，也会尝试其他已记录倍率，以排查“误用其他技能倍率”的问题。

治疗技能只需要名称、治疗倍率和实测显示治疗。

## 计算公式

### 战斗攻击

```text
战斗攻击
= 非战斗面板攻击
+ 基础攻击 × 生效攻击加成总和
```

来自觉醒、武器、弧盘、共鸣和队友的攻击加成都包含在这里。

### 防御、抗性与增伤区

```text
防御区
= (100 + 角色等级)
  / [(100 + 角色等级) + (100 + 敌人等级) × (1 - 防御穿透)]

抗性区
= 1 - 敌人基础抗性 + 抗性削弱

增伤区
= 1 + 通用增伤 + 属性增伤 + 额外增伤 + 生效 Buff 增伤
```

### 常规伤害

```text
非暴击伤害
= 战斗攻击 × 防御区 × 抗性区 × 增伤区 × 最终技能倍率
  × 浸染乘区（若启用）
    或覆纹乘区（若启用）

暴击伤害
= 非暴击伤害 × 暴击伤害倍率

暴击伤害倍率
= 1 + 面板暴击伤害
  + 对该技能生效的通用暴击伤害 Buff
  + 对该技能 Tag / 自定义范围生效的暴击伤害 Buff
```

### 环合强度、浸染 / 覆纹与环合反应

```text
最终环合强度
= 非战斗基础环合强度 × (1 + 百分比提升总和)
  + 固定数值提升总和

浸染 / 覆纹增伤
= 20% + 最终环合强度 / 1400

浸染 / 覆纹独立倍率
= 1 + 浸染 / 覆纹增伤
= 1.2 + 最终环合强度 / 1400

非暴击创生花
= 9000 × 1 × 防御区 × 抗性区 × (1 + 最终环合强度 / 600)
  × 自定义点名增伤区

暴击创生花
= 非暴击创生花 × 暴击伤害倍率

非暴击浊燃
= 2700 × 1 × 防御区 × 抗性区
  × (1 + 最终环合强度 / 600)
  × (1 + 生效持续伤害强化总和)
  × 自定义点名增伤区

暴击浊燃
= 非暴击浊燃 × 暴击伤害倍率

非暴击黯星
= 45000 × 1（无视防御）× 抗性区
  × (1 + 最终环合强度 / 600)
  × 自定义点名增伤区

暴击黯星
= 非暴击黯星 × 暴击伤害倍率
```

因此，把某项额外暴击伤害 Buff 的作用范围设为“仅持续伤害”后，它会与常规暴击伤害加算并作用于浊燃，但不会作用于非持续技能。

创生花、浊燃和黯星不读取面板攻击、默认常规增伤、普通技能倍率、浸染或覆纹乘区；浊燃额外读取持续伤害强化，黯星是无视防御的伤害，因此其防御区永远为 `1`。只有把 Buff 作用范围设为“自定义技能”并明确勾选某个环合反应时，该 Buff 的“增伤”字段才会额外进入该反应公式。

顶部“公式 / FORMULA”页面可检查全部模型的乘区白名单，并修改创生花、浊燃、黯星固定基础值、环合反应除数，以及浸染 / 覆纹的基础增伤和环合除数。验算结果下方会用固定颜色展示本次实际相乘的每个因子。

### 治疗

```text
治疗值
= 战斗攻击 × 治疗倍率 × (1 + 生效治疗加成总和)
```

伤害技能的防御、抗性、增伤、暴击、浸染 / 覆纹乘区均不作用于治疗。更完整的加算、乘算和失效规则见 [docs/formulas.md](docs/formulas.md)。

## 如何理解验算结果

“最符合实测的全局状态”是整批实测值共同使用的一套解释，不是统计学概率，也不是单条伤害的来源。

状态按以下顺序排序：

1. 超过 `±20` 或没有来源的条目更少；
2. 相对误差总和更小；
3. 基础乘区失效更少；
4. 误用其他技能倍率更少；
5. 更少违背“高触发优先”的 Buff 预期；
6. 候选 Buff 单项失效更少。

| 结果字段 | 含义 |
| --- | --- |
| 理论精确值 | 保留小数的内部计算值。 |
| 理论显示值 | 按游戏显示规则四舍五入后的整数。 |
| 误差 | `|理论显示值 - 实测显示值|`。 |
| 显示值总误差 | 本批全部条目的显示值误差之和。 |
| 零误差全局状态 | 整批总误差为 `0` 且没有无来源条目的状态，最多显示 3 项。 |
| ±20 内来源数 | 当前全局状态下，某条未知伤害落入误差范围的候选来源数量。 |
| Buff 优先级违背 | 已配置 Buff 中未生效部分的加权值；越小越符合勾选偏好，不是统计学概率。 |

如果没有零误差状态，顶部仍显示总体最接近的状态用于诊断，但不会把带误差的备选状态列入“零误差全局状态”。

## 搜索范围与性能

| 档位 | 完整枚举上限 | 超过上限后的限宽 | 建议用途 |
| --- | ---: | ---: | --- |
| 标准 | 18 个判断项，最多 262,144 个状态 | 5,000 | 快速反复改数值。 |
| 深度 | 20 个判断项，最多 1,048,576 个状态 | 20,000 | 默认正式验算。 |
| 极限 | 22 个判断项，最多 4,194,304 个状态 | 50,000 | 最终排查，接受更长等待。 |

完整枚举范围内会评估全部 `2^N` 个状态。为了控制内存，计算过程中只保留排序最好的 300 个解释，这不会改变第一名和前三个零误差结果。

超过上限后，程序会从“全部生效”开始逐项排除，并保留当前较好的路径。该模式不是穷举，理论上可能漏掉组合；界面会明确标注当前采用“完整枚举”还是“全生效起点逐项排除”。

EXE 仍使用 JavaScript 计算。打包不会消除数百万状态带来的计算量；极限档或复杂狂暴溯源期间窗口可能短暂忙碌，请等待状态栏显示“验算完成”或“溯源完成”。

## 数据保存与隐私

全部计算、档案和 OCR 都在本机完成。

| 版本 | 数据位置 |
| --- | --- |
| Windows 桌面版 | `%LOCALAPPDATA%\GameDamageCalculator` |
| HTML 版 | 当前浏览器的本地存储 |

程序不会自动上传角色面板、实测伤害或截图。删除应用数据目录或浏览器站点数据后，本地档案无法恢复；重要测试仍建议保留原始拉表记录。
